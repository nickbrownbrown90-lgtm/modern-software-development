The 7 Stages of the Modern Delivery Pipeline

Modern software delivery is an automated, continuous feedback loop rather than a rigid waterfall. A change travels through these stages before serving production users:

1

Discovery, Requirements & RFC (Design)

Translating user pain points and business goals into clear technical specs, user stories, and acceptance criteria.

PRD / Spec RFC (Request for Comments) Acceptance Criteria
2

Local Development & Version Control

Engineers branch from the main codebase (Git), build locally with hot reloading, and write unit/integration tests.

Git Branch Local Dev Server Unit Tests
3

Code Review & Pull Requests (PRs)

Peers inspect the code for readability, security, architectural fit, and edge cases before it merges into the mainline.

Pull Request (PR) Code Review Linters & Formatters
4

Continuous Integration (CI)

Automated cloud servers trigger on every commit/PR: compiling code, running the test suite, and verifying build integrity.

GitHub Actions Test Runner Build Validation
5

Artifact Packaging & Containerization

The application and all its dependencies are sealed into an immutable, portable artifact (such as a Docker image).

Docker Container Container Registry Build Artifact
6

Continuous Delivery & Deployment (CD)

Automated promotion to staging environments for QA, followed by controlled release to production (canary, blue/green).

Staging vs Prod Feature Flags Canary Deploy
7

Observability & Incident Management

Live health monitoring: tracking system telemetry, alerts on anomalies, and rapid rollback when regressions appear.

Logs, Metrics, Traces Alerting (PagerDuty) Post-Mortem

Essential Glossary: High-Value Terminology

Term Plain-English Definition & Executive Context
Continuous Integration (CI) The practice of automatically building and testing every single code change before merging, preventing "merge hell" and broken builds.
Continuous Delivery (CD) The automated capability to release any passing build to production reliably with minimal human friction or downtime.
Pull Request (PR) A proposed set of code changes submitted for peer review and automated testing before being accepted into the main codebase.
Container (Docker) A lightweight, standardized package containing the application code, runtime, and system libraries so it runs identically on any machine or cloud.
Staging Environment A replica of the production environment used to test changes against realistic databases and integrations before real users see them.
Feature Flag A software toggle allowing code to be deployed into production while keeping the feature invisible until intentionally turned on for users.
Observability The ability to understand a system's internal health based solely on its external outputs: telemetry from metrics, logs, and distributed traces.
DORA Metrics Four industry-standard benchmarks for engineering velocity and stability: Deployment Frequency, Lead Time for Changes, Change Failure Rate, and Time to Restore Service (MTTR).
