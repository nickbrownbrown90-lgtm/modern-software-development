Stage 1: Local Development & Git Branching

How engineers write code in isolation and why branch lifespan dictates team velocity.

What Actually Happens on a Developer's Laptop?

Before a feature touches servers, tests, or users, it starts on an engineer's machine. But engineers don't edit live production code. They work inside a local sandbox governed by two pillars:

1. The Local Feedback Loop

Developers run a local development server (e.g. Next.js, Vite, Node). Whenever they change a file, Hot Module Replacement updates their browser in milliseconds without a full page reload. This rapid feedback loop is where 90% of engineering problem-solving takes place.

2. The Safety of Git Branches

To ensure their work doesn't disrupt anyone else, the developer creates a Git branch—an isolated snapshot diverging from the mainline codebase (usually called main): 

git checkout -b feat/user-authentication

Every commit they save here is private to this branch until they choose to share it with the team.

The Core Conflict: Trunk-Based vs. Long-Lived Branches

How an engineering team manages branches is one of the strongest predictors of team velocity and bug count. There are two competing philosophies:

The Dangerous Path (Long-Lived Feature Branches):
An engineer spends 3 weeks building a big feature on their branch. Meanwhile, 5 other teammates merge 40 changes into main. When the engineer finally tries to merge back, the code has drifted radically. Days are lost untangling merge conflicts, and hidden regression bugs slip through.
The High-Performing Path (Trunk-Based Development):
Branches live for 1 to 2 days maximum. Even if a multi-week project isn't finished, small incremental chunks are merged continuously into main behind feature flags (toggles that hide unfinished UI). Merge conflicts vanish because code never drifts far apart.

💬 The Leadership Question

In your next sprint planning or retrospective, ask:

"What is the average lifespan of our feature branches? Are we merging small daily increments, or holding branches open until an entire epic is complete?"

If branches stay open longer than 3–4 days, team members will likely report painful merge conflicts and high integration stress.
